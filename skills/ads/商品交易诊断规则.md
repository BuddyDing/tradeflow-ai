# 商品交易诊断规则（SOP）

依据日期范围报告（交易/结算）做商品级盈亏与问题定位。有导入的交易数据时，调
`analyze_transactions` 拿到按 SKU 的分 type 统计，再按下面规则判读；没有交易数据时，
明确告诉用户需要上传「日期范围报告」，不要臆造。

## 数据口径（必须向用户讲清，不能混淆）
- **销售额（product sales）**：成交金额，未扣任何费用。
- **平台费后到手（total）**：扣掉销售佣金、FBA、退款、税代扣等平台费用后的到手金额，
  **不是净利润**。缺采购成本时只能到这一层，禁止声称具体利润/亏损金额。
- **平台费**：销售佣金 + FBA 费用之和（报表里是负数，取绝对值）。

## 问题商品判定（按影响排序，高销量优先）
- **高退款率**：退款率 ≥ 15%（阈值可调）。→ 结合 description 查退款原因，多为质量/
  描述不符/物流问题；退款率高的高销量 SKU 最该先处理。
- **低毛利**：平台费后毛利率 < 30%（阈值可调）。→ 平台费占比过高或定价过低。
- **负向调整/扣费**：Adjustment 等 type 的净额为负且金额显著。→ 查 FBA 丢失/损坏赔偿、
  纠纷扣费是否异常。

## 输出习惯
- 先给结论（哪些 SKU 有问题、问题是什么、影响多大），再给按 SKU 明细，最后附口径说明。
- 金额保留两位小数，比例用百分数；每个判断都能追溯到 `analyze_transactions` 的字段。

## 部分信息也要出结论 + 引导补数据（重要）
按当前拿到的数据给出**能给的最强结论**，同时说明再补什么能得到更强结论：
- **只有交易报告**：给销售额、平台费后到手、退款率、问题商品；标注「未含采购成本，非净利」。
- **交易 + 成本表**（采购+头程）：可算真实净利、真实毛利率、真实盈亏 ACOS。
- **交易 + 广告搜索词报告**：可判断每个 SKU 广告是否盈利、真实 ACOS 是否超盈亏线。
- 每次分析结束，主动用工具返回的 `next_steps` 告诉用户「再补哪些数据能得到哪些更强结论」，
  而不是停在一句「数据不足」。
